# Bangkok, Your Way — 曼谷 14 人自由行網站 V7

日期：2026/12/1–12/5 · 14 位成人 · 自行包車 · 繁體中文。

## 1. 網站已經能做什麼

- **旅程總覽**：五天共同行程、住宿、必要集合時間。
- **五天主線**：每一天的時間軸、集合地點提示、12/2／12/3／12/4 的 15 條自由分流路線。
- **附近有什麼**：67 個活動／吃喝／休息選項；按日期、區域、興趣、時段、關鍵字篩選。每張卡有停留時間、花費（官方價或估算）與 Google Maps 導航。
- **我的自由行程**：把景點加入指定日期、排序、修改時間、寫備註、自訂新店；產生可直接貼 LINE 的文字行程、分段 Google Maps 路線；可備份／匯入 JSON、下載 TXT、列印／存 PDF。
- **14 人意願登記**：12/2–12/4 下午路線、侏羅紀 Jurassic World、Thainosaur、12/4 晚宴、吃喝與休息偏好。部署 Apps Script 後，所有人使用同一份 Google 試算表進行彙整。
- **地圖**：OpenStreetMap 的商圈概覽（約略中心點）、每個區域或活動都能跳轉 Google Maps；不需要 Google Maps API Key。

**注意：** 只有 GitHub Pages 沒有跨裝置資料庫。未設定 `config.js` 的 `syncEndpoint` 時，個人行程與團員選擇只是儲存在各自瀏覽器。畫面會明確標示「尚未同步」，不會誤導使用者。

## 2. 用 GitHub Pages 上線（網站已可直接部署）

1. 在 GitHub 建立一個新儲存庫（例如 `bangkok-trip-2026`）。避免混入公司的案件或客戶資料。
2. 將此資料夾的 **`index.html`、`style.css`、`app.js`、`data.js`、`config.js` 和 `assets/`** 放在儲存庫根目錄。`build_data.py` 和 `data.json` 可一起放，方便未來編輯活動資料，但不是網站執行所必需。
3. 到儲存庫 `Settings → Pages → Build and deployment → Deploy from a branch`，選 `main` 與 `/ (root)`，儲存。
4. 部署完成後，使用 GitHub Pages 實際顯示的網址開啟（不要猜網址）。網站無登入，知道網址的人可瀏覽行程。
5. 在瀏覽器試：切 12/2 → 點「附近有什麼」→ 篩選「恐龍」→ 加入 Jurassic World →「我的自由行程」→「產生文字行程」→ 點導航。

GitHub Pages 的資料及 HTML 都公開可讀，因此 **不能將團員登記碼、Google 認證資訊、機票護照或個人私密紀錄寫入此儲存庫**。不要在 `config.js` 中放密碼。

## 3. 14 人共用登記：Google Sheets + Apps Script（需要自己設定一次）

這是「共同儲存」的必要步驟，不是單靠 GitHub Pages 自動具有的能力。

1. 在 **個人的 Google Drive** 新建一份 Google 試算表，命名例如「曼谷 2026｜14 人分組登記」。建議與公司案件資料完全分開。試算表不必分享給所有團員。
2. 試算表選 `擴充功能 → Apps Script`，刪掉預設 `myFunction`，貼上 `shared-backend/Code.gs` 全部程式碼，儲存。
3. 在 Apps Script 編輯器上方函式下拉選單選 `setup`，按執行。第一次會要求 Google 授權，請確認這是你自己新建的程式及試算表。成功後會產生 `Members` 和 `RSVP` 兩張工作表。
4. `Members` 有 **01–14 共 14 組個人登記碼**。主揪分別把編號＋對應登記碼私訊給團員，不要公開張貼。若重新執行 `setup()`，已存在的登記碼不會重置。
5. Apps Script 選 `部署 → 新增部署作業 → 類型：網頁應用程式`，**執行身分選「我」**，**有權存取的使用者選「所有人」**（不同帳戶 UI 字詞略異）。完成後複製以 `/exec` 結尾的網址。
6. 回 GitHub 儲存庫，編輯 `config.js`：

   ```js
   window.BKK_CONFIG = { syncEndpoint: 'https://script.google.com/macros/s/你的部署ID/exec' };
   ```

   **只填公開的 Web App 入口 URL，絕對不要填個人登記碼。**
7. GitHub Pages 更新後，在網站「14 人意願登記」選編號、填暱稱和自己的登記碼，選擇侏羅紀與路線後按「儲存我的登記」。必須看到「共用表已確認儲存」才算成功。再按「重新載入團員統計」確認。
8. 第二位團員用另一台裝置登入，確認可以看見第一位的暱稱和意願，但看不到登記碼。**如果第二台看不到，表示同步還未完成，不應宣稱已建立共同登記。**

### 安全與限制

- 這是 14 位熟識旅伴用的**低敏感度行程投票工具**，不是有驗證登入、多因素認證的資料庫。個別登記碼為阻止意外覆蓋的輕量保護，並非金融等級身份驗證。
- `list` API 讀取端點可被有網址的人呼叫，會顯示團員暱稱與選擇。請不要填真實姓名以外的個資、健康狀況、藥物、護照、電話、住址、機票訂位代碼等；隱私優先請使用暱稱。
- 儲存使用 Google Apps Script 的 JSONP 回呼，為跨網域網頁的簡易相容機制。登記碼經 HTTPS 傳遞，但可能出現在 URL／伺服器紀錄；請不要重複使用其他重要密碼。如果要擴大成公開活動或處理個資，應改有正式登入與存取控制的後端。
- `RSVP` 只有團員編號、暱稱、一般選擇與簡短備註。`Members` 登記碼只有主揪可看。
- 若修改 `Code.gs`，需在 Apps Script 的部署管理中建立新版本，使用有效的 `/exec` 網址；只按儲存並不代表已更新公開部署。
- 活動卡「已加入我的行程」**不會自動上傳到共用表**。個人完整安排存在本機，團員統計只收你在「14 人意願登記」表單主動送出的選擇。

## 4. 內容與地圖如何改

- `data.json` 是完整可閱讀資料；原始活動數據也在 `build_data.py`。修改 `build_data.py` 後於本機執行 `python build_data.py`，會重建 `data.json` 和瀏覽器用的 `data.js`。
- `zones` 是大區的概略中心點，不是每個商家店址；所有「精準導航」都會轉 Google Maps 搜尋／路線頁。
- 日期、主線、會合時間在 `days`。某個支線的遊玩組合在 `packages`，個別店家與活動在 `pois`。
- 費用單位全部為泰銖 THB；標「估算」的是人均預留預算，並非店家最新標價；即使標「官方價」，購票前也要再查。
- 預估交通只是**排程緩衝**，不是即時 ETA；Google Maps 導航開啟時才會顯示當下交通資料。
